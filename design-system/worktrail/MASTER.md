# WorkTrail UI 원칙

제품: 메일·JIRA 문의와 수행 기록을 검토하는 로컬 Windows 업무 앱.

장시간 읽고 편집하는 데 맞춘 밝고 차분한 화면을 사용한다. 문의 제목, 본문,
실제 상태와 수행 기록이 시각적 중심이다. 외부 폰트·CDN·런타임 UI 의존성을 추가하지 않는다.

## 지속적인 스킬 활용

모든 GUI 개발·수정·리뷰에는 **Taste Skill과 UI UX Pro Max를 모두 활용한다.**
이 기준은 2026-11-14 개선 작업 이후에도 계속 적용한다.

Taste Skill로 콘텐츠 중심 구성과 시각적 일관성을 검토하고, UI UX Pro Max의
관련 검색과 지침으로 접근성·폼·탐색·반응형을 검토한다. 각 작업의 범위에 맞는
권고를 선별하며 마케팅 웹사이트 전용 효과를 업무 화면에 강제로 넣지 않는다.
원본 확인, 버전 관리, 적용 순서와 완료 기준은 [프로젝트 지침](../../AGENTS.md)을 따른다.

## 시스템

- 색상은 `static/app.css`의 의미별 토큰을 사용한다. 흰 본문, 옅은 회녹색
  탐색 영역, 짙은 녹색 강조색을 사용한다. 경고·오류는 텍스트로도 구별한다.
- 기본 서체는 Windows의 Segoe UI / 맑은 고딕이다. 본문 15px, 목록 제목
  14px, 보조 라벨 12~13px, 화면 제목 28px를 기준으로 한다.
- 간격은 4/8/12/16/24/32/40/48px, 기본 모서리는 6px다.
- 카드 그림자, 배경 그라데이션, 영문 대문자 장식 문구를 추가하지 않는다.
  통계는 얇은 요약 줄로 표현한다. 카드는 실제 작업 영역을 구분할 때 사용한다.
- 메뉴 SVG는 동일한 24px viewBox와 1.5px 선 굵기를 사용한다.
  옆에 이름이 있으므로 접근성 트리에서 아이콘을 숨긴다.

## 탐색과 입력

- 업무 / 기록 / 관리로 메뉴를 묶는다. 현재 화면에는 정확히 하나의
  `aria-current="page"`가 있어야 한다. 초안 목록은 문의함과 별도로 표시한다.
- 화면 제목은 기능의 이름을 쓴다. 버튼은 수행할 행동을 구체적으로 쓴다.
- 입력에는 보이는 라벨을 제공한다. 자주 쓰는 검색 조건을 먼저 보여주고,
  서버·작업·날짜 조건은 상세 필터로 펼친다. 적용 중인 상세 필터는 열린 상태로 유지한다.
- 긴 수행 제안은 문의 제목에서 맥락을 확인한 뒤 원문 전체를 펼쳐 읽을 수 있어야 한다.
- 빈 상태에는 현재 비어 있는 항목과 다음 행동을 알려준다.
- 생성·검토·발송·업무 완료의 의미를 혼동시키지 않는다.

## 접근성과 화면 크기

- 첫 Tab으로 본문 건너뛰기에 도달해야 한다. 모든 조작에 보이는 포커스를 제공한다.
- 일반 텍스트 대비는 4.5:1 이상을 목표로 하고, 새 색상은 실제 배경과 함께 검증한다.
- 작은 화면의 주요 입력·버튼·메뉴는 최소 44 CSS px 높이를 사용한다.
- 700px 이하에서 메뉴는 3열×2행, 입력 폼은 한 열로 전환한다.
- 페이지 전체의 수평 넘침을 허용하지 않는다. 큰 표는 해당 영역 안에서 스크롤한다.
- `prefers-reduced-motion`과 Windows 고대비 모드의 선택 표시를 유지한다.

## 검증

기존 기능 테스트와 `scripts/ui_review.py`를 사용한다. UI 리뷰는 실제 데이터를
쓰지 않는 별도 샘플 서버를 대상으로 하며 초안과 업무일지를 변경한다.
화면·메뉴·라벨·필터·편집·저장·재로딩을 함께 확인한다.

채택 근거와 원본 버전은 [UI 검토 기록](../../docs/ui-design-review.md)을 참고한다.
