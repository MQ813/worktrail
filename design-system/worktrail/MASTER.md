# WorkTrail UI 원칙

제품: 메일·JIRA 문의와 수행 기록을 검토하는 로컬 Windows 업무 앱.

장시간 읽고 편집하는 데 맞춘 밝고 차분한 화면을 사용한다. 문의 제목, 본문,
실제 상태와 수행 기록이 시각적 중심이다. 외부 폰트·CDN·런타임 UI 의존성을 추가하지 않는다.

## 지속적인 스킬 활용

모든 GUI 개발·수정·리뷰에는 **Taste Skill과 UI UX Pro Max를 모두 활용한다.**
이 기준은 2026-11-14 개선 작업 이후에도 계속 적용한다.

Taste Skill로 콘텐츠 중심 구성과 시각적 일관성을 검토하고, UI UX Pro Max의
관련 검색과 지침으로 접근성·폼·탐색·반응형을 검토한다. 각 작업의 범위에 맞는
권고를 선별하며 마케팅 웹사이트 전용 효과를 업무 화면에 강제로 넣지 않는다.
원본 확인, 버전 관리, 적용 순서와 완료 기준은 [프로젝트 지침](../../AGENTS.md)을 따른다.

## 시스템

- 색상은 `static/app.css`의 의미별 토큰을 사용한다. 흰 본문, 옅은 회녹색
  탐색 영역, 짙은 녹색 강조색을 사용한다. 경고·오류는 텍스트로도 구별한다.
- 기본 서체는 Windows의 Segoe UI / 맑은 고딕이다. 본문·목록 제목 14px,
  보조 라벨 12~13px, 실제 콘텐츠 제목 22px, 본문 행간 1.5를 기준으로 한다.
- 간격은 4/8/12/16/24/32/40/48px, 기본 모서리는 6px다.
- 카드 그림자, 배경 그라데이션, 영문 대문자 장식 문구를 추가하지 않는다.
  통계는 얇은 요약 줄로 표현한다. 카드는 실제 작업 영역을 구분할 때 사용한다.
- 메뉴 SVG는 동일한 24px viewBox와 1.5px 선 굵기를 사용한다.
  옆에 이름이 있으므로 접근성 트리에서 아이콘을 숨긴다.

## 탐색과 입력

- 메뉴는 오늘 / 문의함 / 프로젝트 / 운영 상태 4개다. 현재 화면에는 정확히
  하나의 `aria-current="page"`가 있어야 한다. 초안은 문의 안에서 편집하고,
  업무 기록 작성·확정·조회는 프로젝트 상세에서 처리한다. 별도 업무일지 메뉴를 두지 않는다.
- 반복되는 경로·환영·사용 설명·탭 이름 제목을 본문 상단에 쌓지 않는다.
  접근성용 화면 이름은 sr-only 제목으로 제공하고 실제 프로젝트명·문의 제목만 보인다.
  AI 연결과 합성 환경 표시는 sidebar 하단 footer에 둔다.
- 목록의 발신자는 제목과 같은 줄의 보조 정보로 표시한다. 데스크톱 행 높이는
  약 37px, 본문 뷰어 행간은 1.5다. 상세 필터는 닫힌 상태에서 별도 줄을 차지하지 않는다.
- 버튼은 수행할 행동을 구체적으로 쓴다. 빈 프로젝트 구역은 문서 템플릿에
  보존하되 화면에서 빈 카드로 반복하지 않는다. 편집·가져오기 폼은 접어서 시작한다.
- 입력에는 보이는 라벨을 제공한다. 자주 쓰는 검색 조건을 먼저 보여주고,
  서버·작업·날짜 조건은 상세 필터로 펼친다. 적용 중인 상세 필터는 열린 상태로 유지한다.
- 긴 수행 제안은 문의 제목에서 맥락을 확인한 뒤 원문 전체를 펼쳐 읽을 수 있어야 한다.
- 빈 상태에는 현재 비어 있는 항목과 다음 행동을 알려준다.
- 생성·검토·발송·업무 완료의 의미를 혼동시키지 않는다.

## 접근성과 화면 크기

- 첫 Tab으로 본문 건너뛰기에 도달해야 한다. 모든 조작에 보이는 포커스를 제공한다.
- 일반 텍스트 대비는 4.5:1 이상을 목표로 하고, 새 색상은 실제 배경과 함께 검증한다.
- 작은 화면의 주요 입력·버튼·메뉴는 최소 44 CSS px 높이를 사용한다.
- 700px 이하에서 메뉴는 4열, 입력 폼은 한 열로 전환한다. 상태 표시는 메뉴 아래에 압축한다.
- 페이지 전체의 수평 넘침을 허용하지 않는다. 큰 표는 해당 영역 안에서 스크롤한다.
- `prefers-reduced-motion`과 Windows 고대비 모드의 선택 표시를 유지한다.

## 검증

기존 기능 테스트와 `scripts/ui_review.py`를 사용한다. UI 리뷰는 실제 데이터를
쓰지 않는 별도 샘플 서버를 대상으로 하며 초안과 업무일지를 변경한다.
화면·메뉴·라벨·필터·편집·저장·재로딩을 함께 확인한다.

채택 근거와 원본 버전은 [UI 검토 기록](../../docs/ui-design-review.md)을 참고한다.

## AI 자동 반영과 확인 (0.5)

- AI 반영은 실제 문서 변경이고 사용자 확인은 별도 상태다. `AI 반영 · 미확인`, `사용자 확인`, `되돌림`을 텍스트로 표시한다.
- 생성/수정 폼에는 요청, 처리 방식, 대상 프로젝트, 참고 문의의 보이는 라벨을 제공한다.
- 미연결 변경은 기존 프로젝트를 직접 선택해 연결하거나 신규 프로젝트 생성·관리 대상 아님으로 처리한다. 없음과 검색 실패를 단정적으로 동일시하지 않는다.
- 처리 요청 즉시 버튼을 비활성화하고 입력 옆 상태를 알린다. 완료하면 프로젝트로 이동하며 실패/추가 정보는 입력 곁에 표시한다.
- 변경 전후/근거는 펼쳐 확인한다. 확인은 수행 완료나 메일 발송을 뜻하지 않는다.

## 프로젝트 작업 공간 (2026-11-15)

- 상세는 개요 / 하위 이슈 / 수행 기록 / 변경 검토 / 자료·설정으로 나눈다.
  URL로 현재 화면과 선택 이슈를 보존하고 브라우저 뒤로 가기를 지원한다.
- 개요에는 프로젝트 공통 내용만 본문으로 표시한다. 하위 이슈는 최대 4개의
  짧은 미리보기와 전체 목록 경로를 제공하며, 상세 내용을 공통 본문에 섞지 않는다.
- 이슈 목록은 검색과 12개 단위 페이지 이동을 제공한다. 선택한 이슈는 전용 본문과
  전환 목록으로 표시한다. 800px 이하에서는 이슈 전환을 라벨이 있는 선택 상자로 바꾼다.
- 기본 정보는 넓은 화면의 오른쪽 열에 둔다. 긴 내용은 펼쳐 읽고, 구역별 본문은
  최근 3건을 먼저 표시한다. 전체 내용을 잘라 버리거나 CSS로 숨기지 않는다.
- 편집은 내용 가까이에 둔다. AI 입력은 native dialog로 열고 대상 범위를 명시한다.
  프로젝트 요청은 공통 내용과 이슈 목록, 이슈 요청은 선택한 이슈의 내용을 사용한다.
  이슈 범위를 벗어나는 수정은 서버에서 거절한다. 변경 확인·되돌리기는 검토 탭에 둔다.
- 외부 자산 없이 기존 서체·색상·선·간격을 재사용한다. 반복 카드와 장식성 지표를
  추가하지 않으며, 관리·내보내기·이력 도구가 실제 본문보다 먼저 공간을 차지하지 않게 한다.

## 문의함 요약·출처와 연결 검토 (2026-11-15)

- 상단 요약은 실제 필터 링크로 제공한다. 전체 문의 요약을 누르면 다른 검색 조건을
  초기화하고 해당 상태/초안 최신성 조건을 적용한다. 선택 표시와 보이는 폼 값이 일치해야 한다.
- 출처는 텍스트와 배경색을 함께 쓴다. 실제 Jira 이슈는 파란색, 받은 메일은 녹색
  source 토큰을 사용한다. Jira 알림 메일은 받은 메일로 구별한다. 받은 메일 필터에
  실제 Jira 이슈를 중복 포함하지 않는다.
- 미연결이라는 사실만으로 프로젝트 연결 대기라고 표시하지 않는다. 광고·중복 Jira 알림,
  업무 변경의 긍정 근거가 없는 예전 분류를 후보에서 제외하고, 원문은 보존한다.
- 연결 검토 항목에는 선정 이유와 원문 근거, 실제 식별 단서를 표시한다. 단서가 없으면
  구체적인 다음 행동을 안내하며, 검색하지 않은 상태를 검색 실패나 프로젝트 부재로 설명하지 않는다.
- 기존 프로젝트 연결은 대상 선택 → 저장 → 업데이트 요청 → 결과 확인으로 구분한다.
  대상이 없는 경우 임의로 새 프로젝트를 생성하지 않는다. 새 원문 도착 시 재확인을 요구한다.
- 프로젝트 탐색은 아래 승인된 5개 탭을 따른다.
  [프로젝트 탐색 설계](../../docs/project-navigation-proposal.md)를 참고한다.

## 프로젝트 목록·AI 작업 공간 (2026-11-15 승인안 반영)

- 프로젝트의 주 탐색은 프로젝트 목록 / 연결 검토 / 프로젝트 추가 / AI / 작업 이력이다.
  각 탭은 URL로 직접 열 수 있고 현재 위치를 표시한다. 목록에 생성·연결·이력 폼을 쌓지 않는다.
- 프로젝트 추가는 직접 입력 전용이다. 이름·목적을 필수로 받고, 기본 정보와 접힌 Spec을
  제공한다. 입력 옆에는 작성 내용 요약을 둔다. JOB 폴더 가져오기 메뉴/API는 제공하지 않는다.
- AI 탭은 자유 요청과 선택 가능한 대상 프로젝트·참고 문의, 처리 결과를 제공한다.
  신규/기존 여부를 사용자가 반드시 정하게 하지 않는다. 검색은 읽기 전용으로 처리한다.
- 새 AI 작업 공간에서는 생성·수정 결과를 변경안으로 보존한다. 대상·현재 값·수정 값을
  확인하고 직접 편집한 뒤 ‘변경안 반영’으로 저장한다. 생성안은 반영 전 목록에 나타나지 않는다.
  기존 상세의 공통/이슈 AI 요청과 연결 문의의 자동 반영은 기존 범위와 확인·되돌리기를 유지한다.
- 프로젝트 공통 내용과 하위 이슈 변경을 구역별로 구별한다. 넓은 화면은 요청/결과 두 열,
  850px 이하에서는 한 열이다. 짧은 메타데이터는 한 줄 입력, 목적·Spec·기록은 여러 줄 입력이다.
- 처리 요청·변경안 확인·검색 완료·반영 완료·추가 정보·실패를 구별하고, 작업 이력에서
  해당 요청으로 복귀할 수 있게 한다. 오류는 입력 가까이에서 다음 행동과 함께 알린다.
- 요청/작성 중 내용과 목록 필터를 탭 이동 중 유지한다. 반영 전 프로젝트/원문이 바뀌면
  저장을 거절하고 최신 내용으로 재요청하도록 안내한다. 변경안 편집은 사용자 수정으로 이력에 보존한다.
