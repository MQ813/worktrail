# 프로젝트 목록·생성·편집 분리 검토

검토일: 2026-11-15. 현재 FastAPI HTML/CSS/JavaScript + WebView2 기준.
이 문서는 다음 정보 구조의 검토안이다. 이번 수정에서는 문의함 필터/출처와
프로젝트 연결 후보·직접 연결 흐름을 개선하며, 아래 탐색 구조 전체를 적용하지 않는다.

## 추천 구조

프로젝트 안에 **프로젝트 목록 / 연결 검토 / 작업 이력** 탭을 두고,
목록 오른쪽의 **프로젝트 추가** 버튼으로 생성 전용 화면을 연다.
생성은 수행할 작업이므로 목록과 동급인 상시 탭으로 두지 않는다.
프로젝트 편집은 기존 프로젝트 상세의 자료·설정에서 처리한다.

```text
프로젝트
├─ 프로젝트 목록              [프로젝트 추가]
│  └─ 프로젝트 상세
│     ├─ 개요 / 하위 이슈 / 수행 기록 / 변경 검토
│     └─ 자료·설정: 해당 프로젝트 편집·내보내기·문서 가져오기
├─ 연결 검토 (N)
│  ├─ 업무 변경 근거가 있는 미연결 문의
│  └─ 프로젝트 미지정 수행 기록
└─ 작업 이력
   └─ AI 요청의 대기·진행·완료·추가 정보·실패, 결과로 이동

프로젝트 추가 → 생성 전용 화면
├─ 직접 입력
├─ AI로 생성
└─ JOB 폴더 가져오기
```

## 위치와 상호작용

| 현재 목록 아래 항목 | 추천 위치 | 이유 |
|---|---|---|
| 새 프로젝트 | 상단 추가 버튼 → 생성 전용 화면 | 목록 탐색과 여러 필드 입력을 분리하고, 넓은 작성 영역을 확보한다. |
| AI로 프로젝트 생성·업데이트 | 생성은 생성 화면, 업데이트는 대상 프로젝트 상세 | 대상이 없는 생성과 대상이 정해진 편집을 섞지 않는다. |
| 최근 AI 요청 | 작업 이력 탭 | 완료를 기다리거나 실패를 재시도하는 흐름은 지속해서 찾아갈 위치가 필요하다. |
| 프로젝트 연결이 필요한 문의·수행 기록 | 연결 검토 탭 | 원문·선정 이유·연결 대상 선택에 집중한다. 목록에서 검토 대기를 억지로 스크롤하지 않는다. |
| 메일·Jira 연결 | 연결 검토의 명시적 연결 폼 | 기존 프로젝트를 선택하고 연결 결과를 확인한다. AI 검색과 연결을 구별한다. |
| JOB 폴더 가져오기 | 생성 화면의 가져오기 방식 | 파일/경로 입력과 결과 검토가 필요해 목록에 항상 펼쳐 놓지 않는다. |
| 기존 프로젝트 개요·Spec 편집 | 상세의 자료·설정 | 지금 보고 있는 프로젝트의 문맥과 복귀 경로를 유지한다. |

## 탭·drawer·화면·새 창 비교

| 방식 | 적합한 용도 | 이 프로젝트에서의 판단 |
|---|---|---|
| 탭 | 목록·연결 대기·작업 이력처럼 반복해서 오가는 목적지 | 목록을 간결하게 유지하며 대기 건수를 표시하기 좋다. URL에 현재 탭/검색 조건을 보존한다. |
| drawer | 목록 한 항목의 짧은 확인·단일 프로젝트 연결 | 보조 작업에는 가능하지만 생성/전체 편집의 기본 위치로는 좁고 내부 스크롤·포커스 관리 부담이 크다. 지금 연결 폼은 펼쳐 쓰는 방식으로 충분하다. |
| 같은 창의 전용 화면 | 프로젝트 생성, 많은 필드 편집 | 생성에 추천한다. 돌아가기로 목록 필터/스크롤을 복원하고, 미저장 입력을 보호한다. |
| 새 창 | 별도 자료를 나란히 비교해야 하는 명시적 작업 | 기본 생성·편집에는 이점이 적다. 창·포커스·닫기 동작과 미저장 상태만 늘어나므로 기본 흐름으로 쓰지 않는다. |

## 설계 근거와 완료 조건

Taste의 콘텐츠 중심·동일 정렬선·반복 카드/설명 축소를 적용한다.
UI UX Pro Max의 nav-hierarchy, modal-vs-navigation, state-preservation,
keyboard-nav 기준에 따라 주 탐색을 modal/drawer에 넣지 않는다.
사진·히어로·효과·새 프레임워크·외부 폰트는 업무 목적에 필요하지 않다.

적용할 때는 목록 기본 화면에 목록/필터/추가 버튼만 남았는지, 탭마다 URL과
브라우저 뒤로 가기가 동작하는지, 생성 입력이 실수로 유실되지 않는지 확인한다.
연결 검토는 대상 선정 이유·원문 근거·실제 연결과 AI 제안을 구별해야 한다.
작업 이력은 생성/편집 중인 폼을 다시 펼치지 않고도 완료/실패를 확인할 수 있어야 한다.
