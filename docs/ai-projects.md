# AI 프로젝트 생성·업데이트 사용법

## 시작하기

프로젝트는 **프로젝트 목록 / 연결 검토 / 프로젝트 추가 / AI / 작업 이력**으로 나뉜다.
직접 생성은 프로젝트 추가에서 이름·목적·공정·개발 대상·담당자·일정·Spec을 입력한다.
입력 옆에서 작성 내용을 확인할 수 있고, JOB 폴더 가져오기 메뉴/API는 제거했다.

AI 탭에는 자유롭게 요청한다. 신규 생성, 기존 내용 수정, 프로젝트 검색, “기존 대상이면
수정하고 없으면 생성”을 같은 입력에서 처리한다. 대상을 알면 직접 선택하고,
모르면 요청에서 찾게 할 수 있다. 참고 문의도 여러 개 선택할 수 있다.
전체 범위가 크면 대상 프로젝트나 참고 문의 수를 줄이라는 안내를 표시한다.

검색은 내용을 바꾸지 않고 목적·일정·하위 이슈·일치 단서를 보여준다. 검색 결과에서
프로젝트를 선택해 수정 요청을 이어갈 수 있고, 빈 결과에서는 생성 요청으로 이어간다.
생성·수정 요청은 먼저 **변경안**으로 보존되며 실제 프로젝트를 바꾸지 않는다.
이름·메타데이터·기록을 직접 편집하고 **변경안 반영**을 누르면 저장한다.
페이지를 나가거나 새로 열어도 작업 이력에서 해당 요청과 변경안을 다시 열 수 있다.
반영 사이에 프로젝트/참고 문의가 바뀌면 저장을 거절하므로 최신 내용으로 다시 요청한다.

AI 탭의 요청은 공통 내용과 기존 하위 이슈를 함께 수정할 수 있다. 프로젝트 상세 상단의
“AI로 업데이트”는 계속 해당 프로젝트의 개요와 공통 내용을 대상으로 한다.

상세 화면은 개요 / 하위 이슈 / 수행 기록 / 변경 검토 / 자료·설정으로 나뉜다. 개요에서 목적·현재 진행·결정·다음 액션과 기본 정보를 확인한다. cell별 내용은 하위 이슈에서 검색하고 선택한다. 목록은 12개씩 표시하며, 선택한 이슈의 내용은 별도 본문으로 열린다. 각 내용의 “내용 편집”으로 직접 수정하거나 “AI로 편집”으로 요청을 시작할 수 있다.

이슈 상세의 “이슈 AI로 편집”은 선택한 이슈만 수정한다. 프로젝트 공통 요청에는 공통 본문과 이슈 목록을, 이슈 요청에는 해당 이슈 본문만 전달한다. 기존 이슈의 상세 수정은 그 이슈에서 요청한다. 이슈 요청이 다른 이슈나 프로젝트 개요를 바꾸는 결과를 내면 서버에서 거절한다.

예: `28nm Atlas GPIO library 개발 프로젝트 만들어줘. 목표 일정: 2027-03-31. Spec: 1.8V, -40~125도.`

예: `JOB-002의 목표 일정을 2027-03-31에서 2027-04-15로 변경해줘.`

프로젝트 연결 검토에는 업무 변경 근거가 있는 미연결 문의만 표시한다. 선정 이유·원문 근거와 식별 단서를 확인하고, “기존 프로젝트에 연결”을 펼쳐 대상을 선택한 뒤 “선택한 프로젝트에 연결”을 실행한다. 저장 후 업데이트 생성을 요청하고 해당 프로젝트의 변경 검토로 이동한다. 이미 존재하는 프로젝트만 선택할 수 있으며, 새 원문이 도착하면 다시 확인해야 한다. “AI로 프로젝트 찾기·정리”는 해당 문의를 선택한 AI 탭을 열어 기존 대상 검색·업데이트 또는 신규 생성 변경안을 요청한다. “프로젝트 관리 대상 아님”은 해당 revision만 제외한다. 새 내용이 수집되면 다시 후보가 될 수 있다. 광고·중복 Jira 알림·업무 변경 근거가 없는 옛 분류는 자동 연결 후보에 넣지 않는다.

## 반영과 확인

AI 요청은 기존 worker에서 처리한다. AI 탭에서는 결과를 같은 화면에서 확인하고 반영 후 프로젝트의 변경 검토로 이동할 수 있다. 상세의 기존 AI 편집 요청은 완료 후 해당 프로젝트/이슈로 복귀한다. 페이지를 닫아도 작업은 보존되며 작업 이력 탭에서 결과·오류·추가 정보 질문과 변경안을 확인한다. 현재 폼에서 요청을 수정해 다시 실행할 수 있다.

변경안을 반영하거나 상세의 기존 AI 편집이 완료되면 “AI 반영 · 미확인” 이력을 남긴다. 변경 검토 탭의 “내용 확인”은 승인 상태만 변경하며 업무 완료를 처리하지 않는다. 수정은 기존 내용 편집이나 새 자연어 요청으로 수행한다. 변경 전후와 입력 본문·문의 revision을 보존한다. 정보가 없으면 TBD, 상충/모호함은 확인 필요로 기록한다. 대상이 불명확한 결과는 적용하지 않는다.

AI 명령이 적용된 프로젝트는 이후 연결 문의의 신규 변경도 자동 반영한다. 기존 수동 프로젝트는 첫 AI 요청 적용 전까지 이전 미확정 검토 흐름을 유지한다. 이전 미확정 이력은 삭제하지 않는다. 과거 이력 재구성, 삭제, 수행 완료, 상충 결과는 기존 검토 경로를 유지한다. 입력/프로젝트가 생성 도중 바뀌면 재요청이 필요하다.

“변경 되돌리기”는 후속 편집이 없는 경우 이전 본문과 개요를 복원한다. 이력·원문 연결·추가한 하위 이슈 자체는 추적을 위해 남긴다. 신규 프로젝트의 “생성 취소”는 프로젝트를 삭제하지 않고 cancelled 상태로 보존하며 생성 항목을 숨긴다. 후속 편집이 있으면 자동 복원을 차단하고 직접 수정을 안내한다.

프로젝트는 공정·개발 대상·목표 산출물 기준으로 구분한다. AI는 큰 범위/긴 이력에 상세 하위 이슈를 제안한다. 문의 자동 반영처럼 전체 문맥을 사용하는 경로는 변경 6개 이상 또는 기존 기록 20개 이상일 때 상세 하위 이슈를 사용한다. 프로젝트 공통 편집 요청은 공통 내용을 유지하며, 명시적으로 요청한 새 하위 이슈를 추가할 수 있다. 제목 링크로 이슈별 내용을 좁혀 보고 JOB ZIP의 issues 문서로 내보낼 수 있다.

미확인 내용이 있는 Markdown에는 상태를 표시한다. 확정본 내보내기는 모든 AI 변경 확인 후 가능하다. DB v7 snapshot/백업에는 요청과 검토 이력도 포함된다.

## 샘플

`runtime/project-samples-20261115-final`은 업무 DB와 분리된 합성 데이터다. `sample-manifest.json`에 실제 OpenCode 실행 여부·요청 ID·프로젝트 ID를 기록한다.

- 문의 없는 SRAM 타이밍 검증: 미확인 신규 생성.
- Atlas GPIO library: 합성 문의 선택 → API → worker → 실제 OpenCode → DB 자동 반영. 목표 일정/spec과 TBD를 확인할 수 있다. 실제 OpenCode로 목표일 2027-03-31 → 2027-04-15 변경도 반영했다.
- Orion ADC: PVT/노이즈/보고서 하위 이슈 3개와 상세 문서 설정.
- Delta SPI: 사용자 확인 완료 상태 (샘플 시나리오).
- Vega PLL: 기존 항목의 일정 변경, 변경 전후와 미확인 이력.
- 대상 선택 필요 요청: 프로젝트를 잘못 생성하지 않고 질문을 보존.

실행: `dist/WorkTrail/WorkTrail.exe --data-dir D:\codes\worktrail\runtime\project-samples-20261115-final`

샘플 설정은 fake backend로 시작하므로 추가 테스트는 합성 응답이며 실제 AI 판단이 아니다. 실제 OpenCode 생성 이력은 그대로 보존된다. 샘플 생성 재현:

```powershell
.venv/Scripts/python.exe scripts/create_project_samples.py --output runtime/new-project-samples --config "$env:LOCALAPPDATA/WorkTrail/settings.toml" --live
```

새 파일 첨부, 모든 미연결 항목의 일괄 자동 발굴, 의미상 중복의 완전 판별은 이번 범위에 포함하지 않는다. 연도가 없는 날짜와 기술 spec을 추측하지 않는 규칙은 모델 지시와 사용자 확인을 함께 사용한다. 실제 사내 데이터 정확도를 보장하지 않는다.
